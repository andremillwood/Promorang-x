# Momentum Engine V1 Scope

This document defines the first implementation cut that is ambitious but operationally realistic.

## 1. V1 Goal

Ship a credible Momentum Engine that proves:
- digital intent can drive verified physical action
- density can be measured and safely amplified
- completed actions can create persistent memories and perks
- users will return for legacy, not just cash

## 2. In Scope

### 2.1 Moments
- support `digital`, `physical`, and `hybrid` moment types
- explicit proof requirements
- moment cards and detail pages that distinguish task type clearly

### 2.2 Gatherings
- `gatheringThreshold`
- `pulse_state`
- threshold progress UI
- live multiplier activation
- capacity and cooldown settings per venue or moment

### 2.3 Memories
- memory issuance at verified completion
- rarity tiers
- vault screen
- active perks on select memories

### 2.4 O2O Content Moments
- content detail page
- digital interaction tracked inside Promorang
- physical unlock path
- creator-facing O2O conversion reporting

### 2.5 Trust and Proof
- multi-modal proof support
- geofence + rotating code + media as preferred pattern for high-value moments
- moderation tooling for edge cases

### 2.6 Stakeholder Dashboards
- participant: pulse, vault, impact basics
- host: moment performance, gathering formation, attendance quality
- venue: capacity governors, gathering efficiency, redemption tracking
- brand: verified conversion, creator performance, momentum ROI

### 2.7 Agent Readiness
- machine-readable discovery endpoints
- optimization endpoints
- execution-prep endpoints
- legacy and perk portfolio endpoints

## 3. Out of Scope for V1

These should not block the first strategic release:

- memory trading or gifting
- full open creator-to-venue marketplace
- live AR threshold visualization
- user-operated limit orders or autonomous reward curves
- advanced secondary memory economies
- fully autonomous agent execution without explicit user consent

## 4. Product Rules for V1

### 4.1 Language Discipline
Use:
- pulse
- gathering
- memory
- founder
- catalyst
- perk
- momentum

Avoid making V1 feel like:
- an exchange
- a betting app
- a securities product

### 4.2 Safety Discipline
Every gathering-capable moment must support:
- a capacity ceiling
- a cooldown policy
- a proof method
- a venue-side off switch

### 4.3 Simplicity Discipline
The home experience should still reduce to:
1. discover what is forming
2. act safely
3. keep what matters

## 5. V1 Success Criteria

V1 is successful if Promorang can show:
- content-to-visit attribution in real scenarios
- density activation without venue chaos
- repeat visits driven by memory perks
- materially better retention for memory holders than cash-only users
