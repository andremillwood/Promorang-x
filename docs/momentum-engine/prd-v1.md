# PRD: Promorang Momentum Engine

_Status: Strategic framework / implementation V1_

## 1. Executive Summary

Promorang is evolving from a one-off reward platform into a `community and legacy engine` for real-world momentum.

The platform should not be framed as a coupon app, a pseudo-exchange, or a generic creator marketplace. Its defensible category is:

`a real-world momentum platform that turns verified human movement into attribution, loyalty, and cultural memory`

Promorang solves four related problems:

- `Brands` struggle to connect digital attention to verified physical action.
- `Venues` cannot easily monetize atmosphere, density, or coordinated traffic.
- `Participants` may respond to rewards, but need status, memory, and long-term perks to stay.
- `Hosts and creators` need tools to orchestrate energy, not just publish offers.

## 3. Core User Loops

The end-user experience should remain simple even if the backend is sophisticated.

### 3.1 Participant Loop
1. Discover a pulse
2. Join digitally or physically
3. Verify the action
4. Receive reward and memory
5. Return because perks and status persist

### 3.2 Host Loop
1. Publish a moment
2. Shape the action and proof rules
3. Watch density form
4. Trigger gathering status
5. Learn which formats create repeatable energy

### 3.3 Venue Loop
1. Define safe participation conditions
2. Sponsor or host momentum windows
3. Capture verified traffic and redemptions
4. Convert memories into return visits
5. Become a recurring story hub

### 3.4 Brand Loop
1. Sponsor creators, venues, or moments
2. Trigger digital-to-physical action
3. Measure verified movement and outcomes
4. Compare performance across activations
5. Reinvest in the strongest momentum patterns

### 3.5 Creator Loop
1. Publish a content moment
2. Drive audience interaction and physical unlocks
3. Generate co-branded memories
4. Prove O2O conversion
5. Build repeatable local influence

## 5. Core Product Objects

Promorang V1 is built around the following objects:

- `Moment`: the atomic opportunity
- `Gathering`: a moment whose density threshold has been crossed
- `Memory`: the persistent collectible generated from verified completion
- `Perk`: an active utility attached to memory, venue, brand, or status
- `PulseSignal`: the live state of participation and urgency
- `Catalyst`: a user whose activity drives downstream momentum
- `ContentMoment`: a creator-led or sponsor-led digital-to-physical mission
- `VenueNode`: a venue with capacity, proof rules, and efficiency metrics

## 6. Functional Areas

### 6.1 Gatherings

Gatherings are moments with density logic.

Requirements:
- a `gatheringThreshold`
- a `pulse_state` that changes from dormant to forming to live
- a `bonusMultiplier` that activates safely
- a high-contrast pulse UI that signals active momentum
- venue-defined capacity and cooldown guards

### 6.2 Memories and Collectibles

Memories turn verified actions into persistence.

Requirements:
- memory issuance on qualifying completion
- rarity tiers: `common`, `rare`, `epic`, `legendary`
- optional active perk attachment
- a personal vault view
- collection and set logic for long-term retention

### 6.3 O2O Content Moments

Content moments connect digital interaction to physical execution.

Requirements:
- digital entry actions: watch, comment, share, save, join
- content-specific unlock rules
- creator and sponsor attribution
- co-branded memory issuance
- creator-side O2O conversion metrics

### 6.4 Viral Equity and Impact

Promorang should reward people who create momentum, not just consume it.

Requirements:
- early mover incentive
- catalyst attribution for downstream activation
- impact score and catalyst rank
- influence-sensitive bonus programs

### 6.5 Pulse Value and Flow Dynamics

The system may use dynamic incentive logic, but user-facing language must remain human and safe.

Requirements:
- `pulse value`, `flow volatility`, and `surge` bands
- no default reliance on financial language like trading or exchange
- soft tapering, not cliff-drop incentives
- legible urgency without chaos

## 7. UX Philosophy

The design philosophy is `Radiant Pulse`.

Principles:
- dark luxury visual language
- kinetic but not noisy interactions
- thumb-first mobile ergonomics
- app-like layout and persistence
- human-readable journeys despite complex system behavior

The app should feel like:
- a high-end native PWA
- a social coordination layer
- a legacy wallet

It should not feel like:
- a spreadsheet
- a trading terminal
- a coupon farm

### 8.2 Venue Metrics

### 8.3 Participant Metrics
- completed moments
- memory retention rate
- legacy rank progression
- active perks used
- impact score growth

### 8.4 Creator Metrics
- O2O conversion rate
- content-triggered venue visits
- memory unlock rate
- sponsor retention rate

## 9. Strategic Constraints

Promorang should deliberately avoid:

- overusing exchange or securities language
- encouraging physical stampedes
- reward designs that feel like labor instead of experience
- proof flows that are weak against spoofing
- privacy-invasive real-time individual movement exposure

## 10. Product Positioning Statement

Promorang is a real-world momentum engine that converts attention into verified movement, movement into memory, and memory into long-term economic loyalty.
