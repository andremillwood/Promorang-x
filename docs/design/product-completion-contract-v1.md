5. older audits/matrices — backlog evidence only where not superseded

## Purpose

This file is the single execution ledger for finishing the current PROMORANG redesign and canonical-object convergence.

It exists to prevent:
- new conceptual branches before current work is complete;
- page-by-page redesign without shared contracts;
- stakeholder dashboards drifting apart;
- visually polished surfaces shipping on fake/demo state;
- legacy routes and old information architecture remaining promoted by accident;
- completion being declared from screenshots alone.

No new major product family, world system, or dashboard concept should be introduced until the completion gates in this document are closed.

## Completion thesis

PROMORANG is complete for this release when the whole product consistently expresses:

`CANONICAL TRUTH → CANONICAL OBJECT → DESIGN LAB EXPRESSION → ROLE LENS → JOURNEY COMPOSITION → PRODUCTION UI`

The product must feel like one world across participant, creator, host, merchant, brand, agency and admin while preserving different jobs, density, authority and interaction models.

The visual grammar remains:

- WORLD > DASHBOARD
- OBJECTS > CARDS
- ONE MOVE > MANY ACTIONS
- UTILITY IS QUIET
- production absence is meaningful
- no synthetic activity, rewards, attendance, proof, value or history

## Reconciliation with existing plans

### DESIGN.md

This contract preserves the canonical product laws:
- Today is the authenticated center.
- Scenes are persistent social/cultural containers.
- Moments are time-bound opportunities.
- content connects attention to movement and return.
- PromoCard is a primary participant object.
- Progress/Vault retain consequence and history.
- role personalization changes the experience more than the map.
- human outcome leads; internal mechanism follows.
- no fake urgency, fake value, or mechanism-first UX.

# Definition of completion

This programme may be called complete only when:

- every route is classified;
- every primary production surface uses the canonical design/spacing system;
- every stakeholder has a coherent end-to-end journey, not only a dashboard;
- shared objects have deliberate role lenses;
- all creation flows are comprehensible and resumable;
- onboarding reaches first success;
- no fake/demo production state remains on primary paths;
- loading/empty/error/permission/retry/expired states are intentional;
- web/mobile state semantics agree on primary journeys;
- accessibility/performance/trust gates pass;
- exact release head passes available CI and real-record QA;
- A+ release scorecard categories are all 4;
- documentation and rollback/runbook are current;
- PR is merged/deployed only after explicit approval.

## Final human test

Participant, Creator, Host, Merchant, Brand, Agency and Admin should each be able to explain:

1. what PROMORANG helps them accomplish;
2. what they should do next;
3. which canonical object they are acting on;
4. what counts;
5. what is still pending;
6. what value/result follows;
7. where that result lives;
8. what opens next;
9. what they should return to do.

If the person needs internal PROMORANG architecture explained to them, the programme is not complete.
