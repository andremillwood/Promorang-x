# PROMORANG Stakeholder Object System v1

## Purpose

PROMORANG must not pair a world-class participant experience with generic dashboards for the people and organizations that create, fund, operate, verify, distribute, manage or govern the market.

The stakeholder system inherits the Job-First Workspace Standard:

Job → Outcome → Current Move → Proof → Decision → Tools

The design rule is:

> Shared platform truth can be reused; stakeholder work objects must remain specific to the job.

## Creator

Primary work objects:
- Creator Brief
- Opportunity / Mission
- Deliverable Package
- Proof Submission
- Approval Record
- Settlement Record
- Reputation / Work History

Job: choose worthwhile work, perform it, prove it, get approved/paid and build reputation.

Do not hide proof requirements or settlement conditions until after acceptance.

## Host

Primary work objects:
- Moment Run-of-Show
- Audience / RSVP Ledger
- Arrival Board
- Check-In Record
- Guest Exception
- Proof Close / Attendance Reconciliation
- Return Audience List

Job: fill it, run it and prove who came.

RSVP is intent; verified arrival is attendance proof.

## Merchant / Venue

Primary work objects:
- Offer / Product Inventory
- Venue Activation Sheet
- Validation Slip
- Order / Transaction Record
- Redemption Receipt
- Repeat / Retarget List
- Place Record

Job: turn attention into visits, redemptions, purchases and returns.

Never upgrade a claim or redemption into a paid order without evidence.

## Brand

Primary work objects:
- Activation Sheet
- Audience / Outcome Contract
- Budget / Reward Commitment
- Creator Distribution Brief
- Evidence Pack
- Attribution Record
- Scale / Change Decision

Job: create measurable customer movement and know what actually happened.

The Evidence Pack is the brand-facing equivalent of the participant Proof Receipt: compact, auditable and explicit about what can and cannot be concluded.

## Agency

Primary work objects:
- Client Ledger
- Managed Workspace Context
- Client Activation Sheet
- Shared Approval Queue
- Managed Result Pack
- Proposal / Expansion Record
- Portfolio Decision Board

Job: produce an undeniable client result, preserve client attribution, package the proof and expand the account.

The agency must never lose context when operating inside a client workspace.

## Admin

Primary work objects:
- Exception Case
- Verification Case
- Moderation Case
- Payout / KYC Case
- Support Case
- Resolution Record
- Audit Event
- System Health Queue

Job: address the highest-priority exception, resolve it with evidence, and restore healthy operation.

Admin should not open on telemetry theatre. It should open on what requires intervention.

## Shared primitives

The following can be shared across roles when they represent the same truth:
- Proof Receipt
- Evidence / Attribution badge
- Identity / Organization context
- State rail
- Audit event
- Verification stamp
- Settlement record
- Timeline / history
- Blocker / prerequisite record

Shared primitives must not erase role-specific object semantics.

## Design requirements for every role workspace

1. Current identity / organization is explicit.
2. Purpose and outcome are visible before tools.
3. One current move dominates when possible.
4. Blockers / prerequisites are explicit.
5. Proof contract is visible before action.
6. Metrics are real or clearly qualified.
7. Work objects visibly change state.
8. Evidence leads to a decision.
9. Advanced tools are progressively disclosed.
10. Mobile preserves decision hierarchy; desktop may add operational density.

## Next Design Lab sequence

Stakeholder v1 establishes job contracts and signature work objects. Future passes should separately mature:

- Creator opportunity → brief → submission → approval → settlement
- Host prepare → publish → arrivals → proof close → return audience
- Merchant publish → claim/use → validation → transaction → repeat
- Brand outcome → activation → live evidence → proof pack → scale decision
- Agency client portfolio → managed workspace → proof pack → proposal/expansion
- Admin queue → case → evidence → resolution → audit

Each lifecycle should receive the same material, state, trust and operational-depth treatment as the participant economy objects before production convergence.
