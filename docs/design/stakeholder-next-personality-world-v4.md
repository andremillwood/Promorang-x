# Stakeholder Next V4 — Personality & World Convergence

## Purpose

V3 established job clarity, state truth and operational depth. V4 restores the PROMORANG personality established in Participant Next without sacrificing that maturity.

The goal is not to decorate professional software. The goal is to make every stakeholder workspace feel native to the same PROMORANG world while preserving role-specific work objects.

## Locked rule

**Participant Next personality + Stakeholder Next operational maturity.**

PROMORANG should feel like one world with different instruments, not six dashboards with different accent colors.

## Shared semantic grammar

PROMORANG semantic marks remain reserved for product meaning:

- **Move** — outward action, launch, publish, issue, operate.
- **Explore** — signal, possibility, demand, market discovery.
- **Return** — value, customer return, next decision, correction.
- **Proof** — verification, evidence, authoritative record.
- **Kept** — provenance, retained history, ownership residue.

V4 exposes this grammar as a world path for each role. The marks are not utility icons.

## Role worlds

### Creator — Studio field kit

**Primary object:** Commission → proof folio

Material cues:
- taped brief paper;
- purple studio residue;
- draft/version labels;
- reviewer notes;
- proof-gated submission folder;
- provenance/reputation residue.

World path:
**Move → Proof → Return → Kept**

### Host — Backstage field operations

**Primary object:** Run sheet → arrival trail

Material cues:
- run-of-show chronology;
- orange path markers;
- door/pass semantics;
- ticket/stub treatment in proof review;
- explicit exception cards;
- attendance close as retained operational history.

World path:
**Explore → Move → Proof → Kept**

### Merchant / Venue — Counter instruments

**Primary object:** Key → validation → return

Material cues:
- offer instruments with physical notches;
- Key identity rather than generic offer cards;
- terminal-like validation device;
- perforated receipt/slip;
- stamped verified-use residue;
- place history as retained commercial context.

World path:
**Move → Proof → Return → Kept**

### Brand — Activation fieldbook

**Primary object:** Market move → evidence pack

Material cues:
- clay/gold fieldbook treatment;
- evidence-source dots/path;
- accumulating evidence ledger;
- unresolved proof visibly interrupts scale;
- durable Stop / Change / Scale decision record.

World path:
**Move → Explore → Proof → Return**

### Agency — Client operating folio

**Primary object:** Brief → managed result

Material cues:
- explicit client folio tab;
- client ownership residue;
- purple managed-work spine;
- approval boundaries remain visible;
- result pack remains client-owned;
- next proposal returns from evidence rather than projected ROI.

World path:
**Move → Proof → Return → Kept**

### Admin — Evidence archive

**Primary object:** Case → correction record

Material cues:
- archival case-file grid;
- evidence-chain markers;
- append-only correction path;
- settlement records separated by state;
- audit/traceability treatment rather than generic system cards.

World path:
**Proof → Return → Kept**

## What V4 must not do

- do not reintroduce generic dashboard cards as the dominant grammar;
- do not use PROMORANG semantic marks for generic buttons or navigation;
- do not add texture that obscures operational truth;
- do not make different stakeholder objects visually interchangeable;
- do not imply illustrative review records are live production data;
- do not replace live-converged capabilities with V4 mock data.

## Review gate

A stakeholder destination is personality-mature only if:

1. the user can still identify the current job and next action instantly;
2. the signature work object is recognizable without reading the role label;
3. state, history, proof and consequence remain legible;
4. the surface visibly belongs to PROMORANG rather than generic enterprise software;
5. the surface does not simply copy Participant Next layout;
6. role-specific material cues reinforce the actual job;
7. Move / Explore / Return / Proof / Kept are used semantically, not decoratively;
8. the live production capability can inherit the approved object language without requiring a new backend.

## Migration rule

V4 remains the illustrative design benchmark. Production convergence should selectively carry the approved object and material language into the existing live components already identified in PR #128.
