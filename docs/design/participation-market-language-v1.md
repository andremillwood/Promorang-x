# PROMORANG Participation Market Language v1

Status: working presentation contract for `andre/participation-market-v1`

Authority:
1. `DESIGN.md`
2. canonical object/truth contracts
3. public-experience convergence contracts
4. this document for human-facing market language

## Purpose

PROMORANG can keep precise canonical language internally while presenting the market in words normal people naturally understand.

The product must never trade truth for excitement. Human language changes presentation, not state.

## Public market tape

| Canonical / analytical concept | Human-facing expression | Rule |
| --- | --- | --- |
| Demand / interest | **Want** / **What people want** | A Want is interest only. It is never supply. |
| Velocity | **Momentum** | Show only when a real time-series comparison exists. Threshold progress alone is not momentum. |
| Threshold progress | **Gathering** / **Close to target** / **Target met** | A target being met does not create supply. |
| Supply / response | **Open** / **What opened** / **Something is available** | Use only when a real Moment, Offer, access or other response exists. |
| Claim | **Picked up** / action-specific language such as **reserved**, **saved a spot**, **claimed** | Never imply use, attendance or purchase. |
| Verified action | **Follow-through** and the actual verb: **showed up**, **used it**, **bought**, **checked in**, **completed** | The UI should prefer the real action verb over the umbrella term. |
| Demand count | **Voices** where the source is vote-like; **asked for X times** for named-intent counts | Do not say unique people unless deduplication guarantees it. |
| Operator response | **Answer this** / **Make something available** / **Make something happen** | Response remains distinct from outcome. |

The public rhythm is:

`WANT → GATHER → OPEN → PICK UP → FOLLOW THROUGH → KEEP → RETURN`

When real time-series evidence exists, **Momentum** may sit between Want and Open:

`WANT → MOMENTUM → OPEN → PICK UP → FOLLOW THROUGH`

## Copy law

Prefer:
- **I want this too**
- **Add my voice**
- **People want this**
- **People are gathering around this**
- **Close to target**
- **Something opened**
- **Available now**
- **Picked up**
- **They showed up**
- **They used it**
- **They bought**
- **Keep this on PromoCard**
- **Come back when something changes**

Avoid on participant surfaces:
- demand velocity
- supply liquidity
- conversion inventory
- canonical signal
- response object
- verified action count

These terms may remain in code, analytics, data contracts, operator detail, and documentation when precision matters.

## Truth boundaries

- Want ≠ supply.
- Gathering ≠ momentum unless measured over time.
- Target met ≠ something opened.
- Open ≠ picked up.
- Picked up ≠ used.
- RSVP ≠ showed up.
- Claim ≠ purchase.
- Proof submitted ≠ follow-through verified.
- Follow-through must use the actual verified action type where possible.
- PromoCard continuity ≠ entitlement.

## Design Lab expression

The visual system should make the market feel alive without manufacturing activity.

- **Want**: paper/request/slip energy; warm, human, declarative.
- **Gathering**: visible progress and accumulation, not fake live animation.
- **Momentum**: directional Current treatment only when real change-over-time data exists.
- **Open**: a distinct response object enters the world.
- **Picked up**: finite availability visibly decreases only from authoritative inventory.
- **Follow-through**: consequence receipt / proof-backed state.
- **Keep / Return**: PromoCard and Vault continuity.

Use Current, trajectory, tangible objects and Return physics from Design Lab. Do not create a new canonical object family merely for presentation.

## Participant acquisition contract

The first meaningful market action should happen before PROMORANG asks for unnecessary profile work.

Preferred path:

`SHARED OBJECT → ADD MY VOICE / TELL PROMORANG → CONFIRM → KEEP / AUTH IF NEEDED → SAME OBJECT → RETURN`

Do not turn the first interaction into a dashboard onboarding tour.

## Operator response contract

Operator surfaces should read as:

**People want this. Is there something real you can make possible?**

The response flow should carry the originating Demand context forward, but create a separate canonical Moment / Offer / activation / creator response as appropriate.

## Measurement contract

Public copy may be warm. Measurement must remain strict.

Track separately:
- signal views
- recorded wants / votes
- shares
- qualified participants
- watches
- operator response starts
- real responses published
- pickups / claims
- proof submissions
- verified action-specific outcomes
- returns

Never turn an analytics event into canonical market truth.
