# PROMORANG Economy Material & Artifact Depth v3

## Purpose

V1 established system semantics. V2 separated subsystem personalities. V3 addresses the remaining flatness by requiring each economy object to feel like a believable instrument, document, token, artifact or ledger produced by a process.

The benchmark is the Proof Receipt: it feels real because material, edge behavior, information density, trust function and state consequence all agree.

## Governing rule

Every major PROMORANG economy object must define:

1. noun — what kind of thing it is
2. substrate/material — what visual/mental material it behaves like
3. silhouette/edge condition — how its geometry distinguishes it
4. micro-structure — serials, stamps, rails, seams, fields or ledgers
5. state residue — what remains visible after action or validation
6. trust ritual — what must be proven before action
7. consequence — how the object changes after use
8. return path — where the result appears in Today / Discover / Card / Vault / You

Do not solve depth with generic gradients, heavy shadows or pseudo-3D alone.

## Discovery / Demand

- Noun: civic signal instrument
- Material: field board / live demand console
- Edge: calibration rails and lane boundaries
- Micro-structure: counts, geography, velocity, thresholds, response readiness
- Residue: submitted signal, host response, activation state
- Trust ritual: distinguish latent demand from confirmed supply
- Consequence: signal can become pattern, response, then a real Moment only when supply commits

Discovery should feel unfinished while demand is forming. It should not look like a survey form or generic poll card.

## Pieces

- Noun: kept archival artifact
- Material: archival board / certificate / collection plate
- Edge: archive spine, seal zone, edition frame
- Micro-structure: origin, acquisition type, proof class, utility, collection, holder / transfer state
- Residue: earned/bought stamp, transfer seal, provenance trail
- Trust ritual: origin and provenance before market price
- Consequence: ownership may change; provenance must persist

Pieces should feel carried forward, not like screenshots of NFTs or generic collectible cards.

## Piece Marketplace

- Noun: curated cultural exchange
- Material: gallery shelf + acquisition / settlement sheet
- Edge: mounted artifact display + perforated or document-like settlement object
- Micro-structure: holder, provenance, utility, ask, fees, Gem balance, transfer result
- Residue: ownership transfer record and transaction receipt
- Trust ritual: verified provenance and explicit settlement before confirmation
- Consequence: holder state changes and provenance updates

Browse should feel collectible and cultural; settlement should feel sober and contractual.

## PromoKeys / Perks

- Noun: compact access instrument
- Material: matte polymer / access tag / gate token
- Edge: notch, slot or threshold geometry
- Micro-structure: issuer, venue, validity, requirement, state, serial
- Residue: merchant validation punch / used stamp
- Trust ritual: issuer and terms visible before reveal or redemption
- Consequence: used access becomes Proof; it stops behaving as live access

PromoKeys must not look like miniature PromoCards or generic coupons.

## PromoShare / Draws

- Noun: named draw event
- Material: marquee / draw board + serialized ticket stock
- Edge: perforated ticket stubs and result record
- Micro-structure: draw ID, prize, close time, ticket provenance, locked entry set, draw timestamp, claim status
- Residue: immutable ticket batch, result record, winner / claim history
- Trust ritual: every ticket belongs to one named draw and its source is visible
- Consequence: Open → Closing → Locked → Drawing → Result → Claim / Archive

PromoShare must feel theatrical and auditable at the same time.

## Save & Win

- Noun: protected parking draw
- Material: reserve / custody chamber + separate prize chamber
- Edge: sealed reserve frame
- Micro-structure: available Gems, parked principal, ticket allocation, named draw, committed prize source
- Residue: park / return ledger, ticket issue, draw result
- Trust ritual: participant principal never visually merges with prize pool
- Consequence: principal remains attributable to the participant and eventually returns / becomes available according to the rules

The emotional hierarchy is safety first, excitement second.

## Gems

- Noun: spendable internal value
- Material: value ledger / transactional sheet
- Edge: ledger frame
- Micro-structure: source, destination, amount, timestamp, context
- Residue: transaction history
- Trust ritual: every balance change has explicit source and destination

## Points

- Noun: participation trace
- Material: path / progression history
- Edge: open-ended timeline
- Micro-structure: reason earned, activity source, eligibility / progression context
- Residue: activity history
- Trust ritual: never styled as cash or withdrawable value

## Tickets

- Noun: named-draw entry
- Material: serialized perforated ticket stock
- Edge: ticket stub / perforation
- Micro-structure: draw name, serial / batch, source, close state, result
- Residue: expiry, result or claim state
- Trust ritual: tickets never behave like universal currency

## Production gate

Before any V3 economy object is promoted into Participant Next or a canonical production route:

- compare against current production behavior and data
- confirm all real states and error/empty states
- confirm mobile and desktop behavior
- confirm trust/economic copy with actual system rules
- preserve issuer, provenance, redemption, transaction, draw and audit data
- remove illustrative counts, balances, results and claims
- ensure state residue is backed by real records rather than decorative simulation

The goal is not skeuomorphism. The goal is believable product objects whose material and structure reinforce what they actually do.
