# Promorang Experience Direction

## Product Feel

Promorang should feel like a social marketplace for momentum, not a dashboard suite.

The core blend:

- Social media: feed, creator posts, profiles, reactions, sharing, reputation.
- Jobs platform: opportunities, tasks, proof, applications, contributor status.
- Coupons and rewards: offers, claims, unlocks, local perks, reward receipts.
- Community engagement: Moments, venues, hosts, leaderboards, participation trails.
- Ecommerce: product clarity, value cards, purchase/claim confidence.
- Analytics: compact proof and performance receipts, not dashboard sprawl.
- Exchange: Pieces, liquidity, rank, price/volume, conviction and market movement.
- Apple philosophy: restrained interface, clarity, spacing, direct manipulation, calm hierarchy.
- Bauhaus influence: strong grids, simple geometry, purposeful color, visible structure.

## Design Principles

1. Feed before dashboard.
   Users should first see what is happening and what they can do, not a control panel.

2. Action before explanation.
   Every surface should answer: move, attend, claim, back, sponsor, invite, prove.

3. Receipts everywhere.
   Promorang's proprietary value is attribution. Show what happened because of the user.

4. Cards are not the product.
   Cards are allowed for repeated items, but signature surfaces should use rails, timelines,
   maps, tickets, receipts, offer strips, and exchange rows.

5. Role changes tone, not product.
   Creators, users, hosts, venues, and brands should see the same momentum graph from
   different angles instead of being dropped into unrelated dashboards.

## Signature Pattern

The signature Promorang object is the Momentum Trail:

`Signal -> Action -> Proof -> Reward -> Upside`

This should appear as a living trail, receipt, or flow in major surfaces:

- Content Drops
- Momentum
- Pulse
- PromoShare
- Pieces
- Venue and brand views

## Layout Direction

- Primary app surfaces should use a social-feed canvas with a sticky action rail.
- Use compact top context bars, not large dashboard headers.
- Reserve analytics tables for deeper secondary pages.
- Use offer/coupon visual language for rewards and claims.
- Use exchange rows for Pieces and liquidity.
- Use timeline/receipt language for attribution.

## Visual System

- Base: warm Apple-like calm with precise spacing.
- Geometry: Bauhaus blocks, circles, rails, thin dividers, asymmetrical grids.
- Color: Promorang orange as action energy, black/cream as the system, yellow only as reward light.
- Typography: clear sans for product actions, serif only for editorial emphasis and brand moments.
- Motion: subtle state changes, rail progress, hover lift, receipt reveal. No decorative blobs.
