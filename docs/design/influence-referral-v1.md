# PROMORANG Influence, Polls & Referral v1

Status: active product/design contract.

## Thesis

PROMORANG should never ask people to:
- answer a poll merely because a poll exists;
- share PROMORANG merely to grow PROMORANG;
- refer people with an implied promise of money.

Two human questions must always be answered:

> **Why should I add my voice?**

> **Why should I help this move?**

## Poll law: no orphan polls

A participant-facing poll is a **decision tool**, not a content format.

Every poll should state:

1. **Purpose** — what are we trying to learn or decide?
2. **Question** — what choice does the participant actually make?
3. **Consequence** — what can the result influence?
4. **Decision owner** — who is expected to use the result?
5. **Target** — how much participation would make the signal useful, when applicable.
6. **Truth boundary** — the result does not automatically create supply, attendance, purchase, reward or commitment.

### Human poll purposes

#### Choose what should happen next
Examples:
- What should PROMORANG try to unlock next?
- Which experience should a host build?
- Which neighborhood should a pop-up go to?

#### See if other people want this too
Examples:
- Would you want a Sunday sunset house session?
- Should Restaurant X have a first-taste experience?

#### Find what would move people
Examples:
- What would actually get you through the door?
- What value would make you try this?

#### Get a verdict before deciding
Examples:
- Which concept should this community move forward with?
- Which feature / flavor / format is worth testing?

## Poll consequence presentation

Poll cards should lead with:

**WHAT YOUR ANSWER CAN CHANGE**

Then:
- stated consequence;
- who will use it;
- target voices when relevant.

After voting:

> **Your voice is in.**

Then show:
- current result;
- stated next decision;
- optional **Bring more voices** share action.

A threshold is evidence strength, not automatic supply.

## Poll creation language

Avoid:
- Create poll
- Publish survey
- Demand signal
- Record question

Prefer:
- **Ask the crowd**
- **Help choose what happens next**
- **See if other people want this too**
- **Find what would move people**
- **Get a verdict**

The creation form should force a consequence statement before publishing.

## Distribution law

> **Share because it is useful. Credit because it is attributable. Earn because a funded rule exists.**

Distribution is broader than referral.

### Distribution
A person helps a Want, Discovery, Moment, Offer, Challenge, Gig, Content Drop or other useful object travel.

No reward is implied.

### Referral
A person arrives through a recorded referral route and PROMORANG can attribute that person to the referrer.

A referral does not automatically equal a commercial conversion.

### Affiliate
A funded commercial subset of referral/distribution.

An affiliate commission exists only when:
- the opportunity has a configured commission rule;
- attribution is recorded;
- the qualifying commercial action occurs;
- the action is verified under the rule;
- settlement/issuance succeeds.

## The attribution journey

Participant-facing explanation:

> **SHARE → ARRIVE → JOIN → ACT → CREDIT → EARN (IF FUNDED)**

Keep each state separate.

- Share ≠ click.
- Click ≠ signup.
- Signup ≠ activation.
- Activation ≠ purchase.
- Purchase ≠ eligible commission unless a rule exists.
- Commission pending ≠ paid.

## Why someone should share

PROMORANG should prompt sharing only in context.

### After a public Want / poll
> **Bring more voices**

Reason:
- strengthen the signal;
- invite people who care about the same decision;
- help the result become more useful.

### After finding an Offer
> **Send this to someone who would use it**

Reason:
- utility to the recipient.

### After joining a Challenge
> **Challenge someone**

Reason:
- social participation / accountability / team progress where the Challenge supports it.

### After taking a Gig
Sharing is generally not the primary action unless the Gig explicitly requests distribution.

### On a Content Drop
> **Help this move**

Reason:
- distribution is part of the object's job;
- show exactly which attributed action is rewarded, if any.

### After a Moment
> **Bring someone with you**

Reason:
- social utility / attendance, not generic growth.

## Persuasion hierarchy

The product should persuade in this order:

1. **Utility** — this will help / interest the person I send it to.
2. **Influence** — more real participation can strengthen a result or make a response more likely.
3. **Identity / reputation** — PROMORANG can show that I move useful things and people actually act.
4. **Progression** — Points / Keys when explicitly configured.
5. **Money / commission** — only for funded affiliate or Gig rules.

Do not lead the entire network with cash referral promises.

## Referral UX

The referral surface should answer:

### What did my link cause?
- link opens;
- people joined;
- active referrals;
- verified attributed actions;
- recorded reward / commission.

### Is my link tracked?
Generic share:
- useful for distribution;
- no attribution promise.

Recorded referral code:
- later eligible referral activity can be attributed.

### What can I earn?
Show only recorded/configured rule or actual history.

Never synthesize:
- commission rate;
- earning estimate;
- tier;
- conversion;
- points;
- Gems;
- reward.

## PromoShare UX

Every share dialog should show:

### Why move this?
Object-specific human reason.

### How credit works
- share;
- arrive;
- act;
- credit;
- earn if funded.

### Attribution state
- tracked link attached; or
- generic untracked link;
- explicit action to create a recorded referral code.

### Reward state
- show configured reward when one exists;
- otherwise say plainly that no reward rule is attached.

## Operator design

When brands / merchants / hosts / agencies create an opportunity with a distribution objective, they should define:

- desired distribution action;
- who may participate;
- attribution window / route;
- qualifying downstream action;
- reward / commission type if funded;
- proof / verification;
- caps / budget;
- settlement rule.

This can power:
- referral programs;
- affiliate programs;
- ambassador programs;
- creator distribution;
- bring-a-friend mechanics;
- community activation.

These are different commercial configurations of the same distribution infrastructure.

## Reputation layer

Longer term, PROMORANG should distinguish:

- **Reach** — how many people opened from me.
- **Activation** — how many became active.
- **Follow-through** — how many completed the target action.
- **Value moved** — only where financial value is reliably attributable.

This is more useful than a vanity follower count.

## Success test

A participant should never need to ask:

> Why would I answer this?

or:

> Why would I share this?

The interface should already show the answer before the action.
