# Participant reference implementation

Source: four supplied September 27 Promorang mockups. Participant product only; preserve approved public marketing and operator tools.

## Composition and acceptance
- Black canvas, DM Sans, orange contextual actions; compact city/header and five-position mobile navigation with a central Ask.
- Today: short photographic search hero, circular category rail, large real Moment artwork, mixed real feed, canonical Wants with support and actual operator responses. No oversized credential interrupting discovery.
- Moment: artwork, practical date/place, real reservation/check-in actions and an authoritative journey trail. Verification distinguishes pending, rejected and verified; only issued memories/access are kept/unlocked.
- Card: personalized orange identity treatment, actual membership/identity, separate usable credentials and owned offers. No invented portrait, tier, reward or balance.
- Vault: default photographic Pieces grid joined to canonical Moment artwork, detail with actual provenance and recorded participation timeline. Unknown artwork has an explicit placeholder. Financial backing remains separate.
- Scene collections derive from actual collections; evolution/crossovers and cultural traits must come from published rules/verified facts. Do not manufacture these engines in presentation.
- Responsive: 360/390/768/1440 widths, no viewport overflow, 44px touch actions, readable dense text, safe bottom navigation, focus and reduced motion.

## Five-pass convergence loop
1. Composition: participant shell, Today, feed and canonical Wants.
2. Continuity: Moment/proof trail and production API routing.
3. Ownership: Card, photographic Vault, provenance detail.
4. State and responsive verification: populated, empty, failure, pending/rejected/verified, expired access.
5. Finish: visual review, focused tests, build, exact commit production deployment and live checks.

## Capability boundary
Existing services support demand support/responses, RSVP/check-in, proof review, memory issuance and offer fulfillment. Dedicated crossover rewards/evolution rules and cultural DNA scores are not published by the current API. Expose actual collection/history and identity, not imaginary entitlements or arbitrary percentages.

## Completion record
All five convergence passes are complete for the existing participant product capabilities. See `reference-review.md` for source boundaries, findings, verification and deployment handoff. The unpublished crossover/evolution reward engines and cultural DNA scoring are explicitly outside this release; this is not a claim of backend feature parity with the mockups.
